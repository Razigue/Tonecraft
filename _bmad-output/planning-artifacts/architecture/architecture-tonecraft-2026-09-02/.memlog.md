- (version) Web-verified 2026-09-02: Astro 7.2.10 (2026-08-31), not the 5.x my training assumed. Svelte 5.57 current, Svelte 5 still the major, SvelteKit 3 in preview and not used here. Emscripten 6.0.x current (5.0.7 was the April 2026 stable, 6.0.3 shipped July 2026). RTNeural 1.0.0, header-only usable, compile-time API is the fast path.
- (constraint) Relaxed SIMD ships in Chrome 114+ and Firefox 145+ but stays behind a flag in Safari as of 2026. More decisively: relaxed SIMD is DEFINED to allow engine-specific floating-point rounding differences. That directly breaks NFR-6 determinism and would make a shared tone link render differently per engine. Must be forbidden.
- (version) Emscripten 6.0.3 added FMA intrinsics, usable as -msimd128 -mfma (deterministic, emulated) or -mrelaxed-simd -mfma (hardware, non-deterministic rounding). Only the first is compatible with NFR-6.
- (constraint) W3C ConvolverNode convolution architecture is NON-NORMATIVE: the spec itself calls a well-optimised real-time convolution engine one of the hardest parts to implement, and behaviour differs per browser. A ConvolverNode cab therefore renders differently in Chrome, Firefox and Safari.
- (decision) OI-4 RESOLVED: cab IR is a direct-form SIMD FIR inside the single worklet. No ConvolverNode, no FFT library. Binds FR-6, NFR-6, FR-14. Prevents per-browser cab rendering and a node boundary mid-chain. IR capped short (~1024 taps at 48 kHz, 21 ms) which is what makes direct form affordable at roughly 1 percent of a core.
- (decision) Decisive argument for the cab was not the memory copy at the node boundary but determinism plus non-duplication: the W3C convolution architecture is non-normative so ConvolverNode differs per browser, and build-time renders run outside the browser where no ConvolverNode exists, so a custom convolution has to be written regardless.
- (decision) Working mode: Coaching path. Deliverables: the spine plus an interactive HTML+SVG architecture deck.
- (constraint) -mrelaxed-simd is FORBIDDEN. Relaxed SIMD permits engine-specific float rounding, which breaks NFR-6 determinism and makes a shared tone link render differently per browser. Compile with -msimd128 only; -mfma is allowed only in its deterministic emulated form.
- (decision) Build-time renders load the SAME .wasm binary the browser loads, driven from Node. One compilation target, identical bytes. FR-6 becomes structurally true rather than a rule someone must remember.
- (decision) CI (GitHub Actions) compiles the WASM with a pinned Emscripten, runs the renders, deploys to Pages. No binary is ever committed. Prevents wasm and audio drifting apart, and keeps binaries out of git history forever against the 1 GB repo limit.
- (decision) Model weights ship as a binary Float32 blob with a short header, loaded into RTNeural at init. Bit-exact, no parse cost, and it keeps an amp as loadable content so amps 2 and 3 can stay lazy-loaded in v1.1.
- (decision) Parameter schema append-only, forever. Parameters are added, never removed, renamed or repurposed. A tone link from any version always opens and always sounds the same. Consistent with the determinism already committed in NFR-6.
- (decision) A tone link pins the amp identity AND the weights version. Those weights stay served indefinitely, about 7 kB per version. Freezing parameters alone is not enough: identical parameters through revised weights is a different sound.
- (decision) The tone link encodes ENGINEERING UNITS (dB, Hz, ratio, ms), never normalised fader positions. Taper curves are a UI concern only. Consequence: redesigning the UI or retuning a taper cannot change how an existing shared tone sounds.
- (decision) Analytics binds to GoatCounter. Custom events confirmed supported, which FR-47 needs; named in CLAUDE.md section 2; open source so self-hosting stays available. Cloudflare Web Analytics recorded as unverified for custom events rather than rejected.
- (decision) Paradigm: pipes-and-filters. The chain is an ordered sequence of stages with a uniform block interface, composed once at build and once at runtime over the same stage implementations.
- (decision) The main thread owns chain state as the single source of truth (nanostores). The worklet is a sink for parameters and a source only for measurement. Metering is one-way and lossy-tolerant: a dropped metering frame must never affect audio or state.
- (decision) Non-linear stages must stay contiguous in the chain so one oversampling window covers them. This constrains any future reordering feature and is the reason promoting Drive to Must was affordable.
- (decision) With -fno-exceptions the flat C interface returns status codes and process() can never fail: it always produces audio, silence at worst. No error path in the audio thread.
- (assumption) Repo shape: one package, plain directories, no workspace tooling. Solo project; workspaces add ceremony without buying isolation anyone needs.
